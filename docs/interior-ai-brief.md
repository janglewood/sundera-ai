# Бриф про проект: AI-приложение для редизайна интерьера

## 1. Обзор продукта

**Что делаем:** подписочное приложение, которое по фото комнаты пользователя генерирует фотореалистичный редизайн интерьера в выбранном стиле, сохраняя структуру помещения (стены, окна, перспективы).

**Аудитория:** домовладельцы/арендаторы, которые хотят увидеть варианты редизайна перед покупкой мебели/ремонтом; вторичная аудитория — агенты по недвижимости (virtual staging пустых квартир под продажу/сдачу).

**Ключевое ценностное предложение:** за секунды и без дизайнера увидеть, как будет выглядеть своя реальная комната в новом стиле — дешевле и быстрее, чем консультация дизайнера.

**Платформы:**
- Веб-приложение (mobile-first) — основная точка входа на старте
- React Native приложение (iOS + Android) — добавляется после первой валидации трафика, для retention (push) и ASO-канала

**Генерация изображений:** через облачные AI-API (не on-device). Реализация должна быть скрыта за внутренним generation-сервисом, чтобы провайдера можно было менять без переписывания остального приложения — рынок image-API быстро меняется по цене/качеству.

## 2. Пользовательский слой (MVP)

1. **Онбординг** — 2–3 экрана с value prop + примерами "до/после", без обязательной регистрации до первой генерации (регистрация — после того как человек увидел свой первый результат, не до)
2. **Загрузка фото** — из галереи или с камеры (одна комната на фото)
3. **Выбор типа помещения** — гостиная / спальня / кухня / ванная / кабинет / детская (влияет на подсказки модели)
4. **Выбор стиля** — 10–15 курьерских стилей (модерн, скандинавский, минимализм, лофт/индастриал, бохо, японский, классика, прованс и т.п.) + опциональное текстовое уточнение
5. **Генерация** — запрос в облачный API, экран ожидания с прогрессом (целевое время ответа ≤ 15–20 сек воспринимаемое пользователем)
6. **Результат** — 2–4 варианта на один запрос, слайдер "до/после"
7. **Действия с результатом** — сохранить, поделиться (важно для органического роста через TikTok/Pinterest — см. п.6), сгенерировать ещё раз/другой стиль
8. **Пейволл** — после исчерпания бесплатных генераций показываем экран подписки

## 3. Функциональность MVP (обязательный набор)

- [ ] Загрузка фото (галерея + камера)
- [ ] Выбор типа помещения (влияет на промпт/кондиционирование модели)
- [ ] Выбор стиля из курьерского набора + свободный текстовый ввод + голосовой ввод (speech-to-text)
- [ ] Генерация редизайна через OpenRouter (единый Image API, доступ к Gemini/Nano Banana, GPT Image 2, Flux и др. одним ключом) с сохранением структуры помещения через image-editing режим модели
- [ ] 2–4 варианта результата на один запрос
- [ ] Слайдер "до/после"
- [ ] Сохранение результата на устройство
- [ ] Шеринг результата (шаринг-лист платформы, ссылка на веб-версию картинки)
- [ ] История генераций в аккаунте пользователя
- [ ] Регистрация/авторизация (email, Apple Sign-In, Google Sign-In)
- [ ] Бесплатный тир с лимитом генераций + экран пейволла (без реального биллинга на этом этапе — см. backlog)
- [ ] Базовая аналитика воронки: регистрация → первая генерация → просмотр пейволла → оплата

### Явно НЕ входит в MVP (backlog для следующих раз)

- **Реальный биллинг** (Stripe / StoreKit / Google Play Billing) — пока убрано из MVP; экран пейволла есть, но оплата не подключена
- Редизайн по **видео** (с видео нет решённой задачи покадровой согласованности стиля — это отдельная и существенно более сложная ML-задача, чем работа с одним фото; на MVP закладываем только фото, видео — отдельная фаза после валидации основного продукта)
- Ландшафтный/наружный дизайн (другой конвейер сегментации, другой каталог стилей)
- On-device/локальная генерация
- 3D-сканирование помещения (RoomPlan/LiDAR), AR-предпросмотр
- Точная привязка мебели на картинке к конкретному товару (shoppable с точным SKU) — на MVP максимум простой блок "похожие товары" как гипотеза, без обещания точного совпадения
- Мультикомнатные проекты/поэтажные планы
- Участие живого дизайнера в проверке результата
- Инструменты для про (агентства недвижимости, дизайн-студии, API-доступ)

## 4. Подписочная модель и цены (стартовая гипотеза, требует A/B-теста)

Ориентир — рыночные цены конкурентов ($4.50–49/мес в категории, с почти универсальным паттерном "3 бесплатные генерации") и себестоимость генерации с облачных провайдеров (от $0.003 до $0.05 за изображение в зависимости от модели — то есть при подписке $7–15/мес маржа получается очень высокой даже при щедрых лимитах).

| Тир | Цена | Лимит | Что включено |
|---|---|---|---|
| **Free** | $0 | 3 генерации навсегда (не в месяц) | Полное качество, без вотермарки — чтобы шеринг результатов в соцсетях работал как канал роста |
| **Starter** | $6.99/мес | 30 генераций/мес | Стандартная очередь, 2 варианта на запрос |
| **Pro (Unlimited)** | $12.99/мес | Безлимит (fair-use порог, напр. 300/мес) | Приоритетная очередь, 4 варианта на запрос, экспорт в высоком разрешении, безлимитная история |
| **Pro Annual** | $79/год (≈ $6.58/мес) | То же, что Pro | Экономия ~49% к месячной цене — снижает отток в межсезонье |

**Важно для реализации:** бесплатный тир теперь стоит реальных денег (облачная генерация, не on-device) — нужен жёсткий серверный лимит на аккаунт/устройство и защита от повторной регистрации ради новых бесплатных генераций (device fingerprint / ограничение по email-домену на первое время).

## 5. Технические заметки для реализации

**Frontend (веб):** Next.js, mobile-first responsive UI. Экран пейволла — заглушка/UI без реальной оплаты (см. backlog).

**Мобильное приложение:** React Native (рекомендуется Expo для скорости итерации), тот же backend/API, что и у веба. Так как вся генерация происходит на сервере, RN не создаёт узких мест по производительности.

**Backend:**
- API-слой (auth, загрузка фото в объектное хранилище — S3/R2, оркестрация генерации)
- Генерация — асинтронная (job queue + polling или websocket для статуса), т.к. ответ облачной модели занимает секунды, а не мс
- **Generation service — через OpenRouter Unified Image API.** Единый ключ и один эндпоинт (`/api/v1/images`) дают доступ к 30+ моделям от разных провайдеров (Google Gemini/Nano Banana, OpenAI GPT Image 2, Black Forest Labs/Flux и др.) с роутингом и failover между ними, без наценки OpenRouter сверх цены провайдера. Для сохранения структуры комнаты — использовать модели с сильным instruction-following image-editing (напр. Gemini/Nano Banana, GPT Image 2: подаём исходное фото + текстовую инструкцию на смену стиля, а не классический ControlNet-пайплайн). Перед финальным выбором конкретной модели — сравнить 3–5 моделей из каталога OpenRouter на одинаковых тестовых фото по цене/скорости/качеству сохранения геометрии комнаты
- Хранение изображений — с CDN для быстрой отдачи before/after
- Голосовой ввод — speech-to-text на клиенте (Web Speech API в браузере / Speech framework в RN) перед отправкой текста в промпт, отдельного бэкенд-сервиса не требует
- Аналитика — PostHog/Amplitude/Mixpanel, обязательно с воронкой free→paid

**Ограничения качества, которые нужно закладывать в ожидания:**
- Структурное сохранение комнаты (стены/окна/перспектива) при реставйлинге требует режима image-editing с передачей исходного фото модели, а не чистого text-to-image — иначе результат будет "похожая комната", а не "своя комната в новом стиле"
- Между разными облачными моделями будет заметный разброс качества — нужен этап ручного сравнения 3–5 моделей на одинаковых тестовых фото перед запуском

## 6. Метрики успеха MVP

- Конверсия free → paid
- D1/D7/D30 retention (у категории исторически высокий отток после однократного использования — нужно закладывать retention-механики: push с напоминанием попробовать другой стиль/комнату, а не только сам продукт)
- Средняя стоимость одной генерации (контроль маржи)
- Виральность: доля пользователей, которые поделились результатом

## 7. Открытые вопросы для следующих итераций (не блокируют MVP)

- Ландшафтный дизайн как отдельный режим/продукт
- Shoppable-мебель с точной привязкой к товару и партнёрская монетизация (какие партнёрские сети/бренды, не только Amazon — с мебельных брендов условия обычно лучше)
- Видео как формат ввода
- AR-предпросмотр / 3D-сканирование комнаты
